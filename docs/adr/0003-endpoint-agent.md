# ADR-0003: 엔드포인트 에이전트 아키텍처 (관리자 콘솔 + 클라이언트 에이전트)

## 상태

Accepted

## 맥락

브리프의 미래 확장(원격 전원 관리, M5)을 실제로 착수한다. 목표: **관리자가 사내망 PC들을
파악·제어**한다 — (1) 어떤 PC에 에이전트가 설치됐는지 보기, (2) 원격 접속, (3) 업무시간 종료 후
연장근무자 외 PC 자동 종료. 이는 표준적인 **엔드포인트 에이전트(RMM류)** 구조다.

**이 기능의 성격**: 본인이 관리하는 사내망의 정당한 자산·전원 관리다. 다만 직원 PC를 끄고 제어하는
강력한 기능이므로 **인증·부드러운 종료·감사**를 설계에 못박는다(아래 "안전장치").

## 결정 (사용자 선택)

| 축 | 선택 |
|---|---|
| 프로젝트 구조 | **지금 저장소 확장** — `Admin.App`(현 스캐너가 콘솔로) + `Agent`(클라이언트 트레이) + `Shared`(통신 규약) |
| 통신 | **LAN 직접** — 콘솔이 각 에이전트의 TCP 포트로 직접 명령(서버 없음). 인터페이스로 추상화해 후일 중앙 서버 확장 여지 |
| 설치 권한 | 에이전트 설치관리자가 **관리자 권한으로 방화벽 인바운드 허용**(netsh)·자동시작 등록을 설치 단계에서 처리 |
| 원격 접속 | **Windows RDP 활용** — 에이전트가 RDP 허용/안내, 콘솔에서 `mstsc /v:<ip>` 실행. 종료·재부팅·잠금·메시지는 자체 구현 |
| 자동 종료 | **스케줄 + 수동 둘 다** — 에이전트가 로컬 스케줄로 종료(경고→저장유예→연장), 콘솔에서 즉시 종료/연장도 |

### 구성 요소

```
sh-ip-scanner/  (저장소 확장 — "sh 관리 도구" 모음으로)
├── src/ShIpScanner.App/         # (기존) 관리자 콘솔 — 스캔 + 에이전트 상태 + 명령
├── src/ShIpScanner.Core/        # (기존) 스캔·대역·이름조회
├── src/ShIpScanner.Shared/      # (신규) 콘솔↔에이전트 공통 통신 규약·클라이언트·서버·스케줄러
│   ├── Protocol (CommandType, CommandRequest, AgentStatus, CommandResponse)
│   ├── AgentProtocol (포트·프레이밍·직렬화)
│   ├── CommandServer (에이전트측 TCP 수신 → ISystemController 로 위임)
│   ├── AgentClient (콘솔측 연결 → 상태조회/명령)
│   ├── ISystemController / TestSystemController
│   └── ShutdownScheduler (다음 종료시각·경고·연장 판정 — 순수 로직)
├── src/ShIpScanner.Agent/       # (신규) 클라이언트 트레이 앱(Avalonia TrayIcon) + WindowsSystemController
└── installer/agent/             # (신규) 에이전트 설치관리자(Inno, 방화벽·자동시작)
```

### 통신 프로토콜 (LAN 직접, MVP)

- 에이전트가 **TCP 포트(기본 47101)** 로 수신. 콘솔이 접속해 **1요청/1응답**(개행 구분 JSON).
- 명령: `Status`(호스트명·버전·로그온 사용자·다음 종료시각), `Shutdown`, `Reboot`, `Lock`,
  `Message`(안내 표시), `ExtendSession`(연장).
- **인증**: 모든 요청에 공유 토큰(AuthToken). 불일치는 거부 → 아무나 네트워크에서 PC를 끄지 못하게.
  (MVP는 고정 공유키. 이후 per-agent 키/인증서로 강화.)

### 콘솔의 "설치 여부" 판별

스캔으로 살아있는 IP 각각에 대해 **에이전트 포트로 Status 프로브** → 성공하면 "에이전트 설치됨 vX",
실패하면 "미설치". 바둑판 셀에 표식으로 표시.

## 안전장치 (필수 — 설계에 못박음)

1. **인증된 명령만 수락** (AuthToken). 콘솔↔에이전트 공유 비밀.
2. **부드러운 종료**: 즉시 강제 종료 금지. 경고 카운트다운 → 저장 유예 → **연장근무자 연기 가능** → 종료.
   데이터 손실 방지 + 연장근무 예외 처리.
3. **감사 로그**: 언제/누가/어떤 명령을 보냈는지 에이전트·콘솔 양쪽 기록(향후 중앙 서버 시 중앙화).
4. **범위 한정**: 관리 대상은 본인이 관리하는 사내망. 에이전트는 지정된 포트/명령만.

## 근거

- **LAN 직접**은 서버 운영 부담 없이 가장 빠르게 동작(같은 네트워크). 여러 대역은 라우팅/방화벽 허용으로
  커버, 부족하면 `ISystemController`/전송 계층을 인터페이스로 뒀으니 중앙 서버로 확장 가능.
- **RDP 활용**은 검증된 원격 데스크톱을 재사용 — 자체 원격 화면 제작(대형 작업)을 피한다.
- **에이전트 로컬 스케줄**은 관리자/서버가 꺼져 있어도 자동 종료가 동작하게 한다(신뢰성).
- **저장소 확장**은 스캔·대역설정·패키징·라이센스 자산을 그대로 재사용한다.

## 결과

- 긍정: 빠른 MVP, 자산 재사용, 확장 여지(서버/키 강화) 열림, 안전장치 내장.
- 부정/리스크: LAN 직접은 다중 대역에서 방화벽·라우팅 설정 필요. 공유 토큰은 초기 보안 수준(강화 필요).
  강제 종료는 데이터 손실 위험 → 부드러운 종료로 완화. RDP 의존(윈도우 에디션·정책 영향).
